Findings: one `h1` per page, no skipped heading levels, landmarks present once, real links everywhere, images with alternative text and dimensions, dates and authors from WordPress, ACF content (page lead, hero fields, site settings) rendered in PHP and present in the HTML. Nothing is hidden from visitors and shown to bots, and nothing is generated: no FAQ, no boilerplate text, no keyword blocks.

The display name of an author is editorial content: the theme shows what WordPress shows. The structured data applies the privacy rules of `04-structured-data.md` §4 independently.

## 2. Automated checks

- `tests/e2e/semantics.spec.js` (production Playground): for the home, a page, a nested page, a post, a category and a search page it asserts one `h1`, no skipped heading levels, `html lang`, one `main`, one top-level `header` and `footer`, the skip link, labelled `nav` elements, no empty or `javascript:` links in header, main and footer, every image with `alt`, `width` and `height`; machine-readable dates and the public author link on posts; `h2` cards under listings. With JavaScript disabled it asserts the main content, the navigation links and the footer are present and visible.
- `node tests/seo-report.mjs --url …` now reports `html lang`, the heading outline (with skipped levels), images without `alt`, links without a real `href`, and lists them under "Duplicates" so a client site can be checked in one run.
- Visual verification of accessibility (contrast, focus, motion) stays with the existing Playwright suite and manual review; nothing here replaces it.

## 3. Guidance for client content (no automation)

- Use the page lead for the one-sentence summary of a page: it becomes the meta description and the WebPage description without any extra field.
- Keep the first heading of the content an `h2` (the page title is the `h1`); the hero block can replace the page title only when "use as page title" is on.
- Give every image an alternative text in the media library; decorative images are rendered with an empty `alt` by the components that know they are decorative.
- Dates and authors come from WordPress: keep the modified date meaningful (edit the content, not the metadata) and give authors a public display name.
- FAQ sections, if a page needs them, are normal content (the accordion component exists); they are not turned into FAQ structured data, which Google no longer shows.
- Custom post types registered by a site keep the same templates and the same guarantees; add a dedicated template only for different content, not for SEO.
