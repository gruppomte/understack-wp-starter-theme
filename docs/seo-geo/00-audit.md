Source check (28.6): Yoast removes core `rel_canonical` and the adjacent rel links when it registers its head callback (`wp_head` priority 1), merges its own directives into core's `wp_robots` filter at priority `PHP_INT_MAX - 10` (core keeps printing the single tag) and enforces index/noindex congruence inside its own callback only. Yoast disables core sitemaps (`/wp-sitemap.xml` 301 → `/sitemap_index.xml`, which answers 200), and replaces the virtual `robots.txt` body with its own block (`Disallow:` empty plus its Sitemap line). Detection: constant `WPSEO_VERSION`, class `WPSEO_Options`, function `YoastSEO()`. Head marker `This site is optimized with the Yoast SEO plugin`. Yoast emits no description when the post has none set (no automatic excerpt fallback in the default templates); the home title ends with a dangling separator because the tagline is empty (default template `%%sitename%% %%page%% %%sep%% %%sitedesc%%`).

### 4.4 Observations that shape the design

- Both providers own title, description, robots, canonical, social metadata, the JSON-LD graph, the sitemap and the `robots.txt` body as soon as they are active. Any theme output in those domains would be a duplicate.
- The two providers treat robots differently. Yoast keeps core's `wp_robots` output and merges into it; Rank Math removes every `wp_robots` filter when it builds its head on `wp` and prints its own tag. A theme filter on `wp_robots` is therefore merged by Yoast, discarded by Rank Math (or, if added after `wp`, printed by core as a second robots tag). Environment directives must go through `wp_robots` with core and Yoast, and through `rank_math/frontend/robots` with Rank Math.
- Neither provider is "present" in a reliable way until its front-end bootstraps (Rank Math registration gate). Detection must be based on constants/classes, not on an activation flag alone, and the fallback must be computed late (at `wp` / `template_redirect`), not at plugin load.
- The local site has no WooCommerce and no WPML; those paths can only be designed against documented hooks (section 8) and tested later.

## 6. Duplicate-output and compatibility risks

| Risk                                 | Where it comes from                                                                                            | Mitigation to design                                                                                                                                                                                                                                                 |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Two canonicals                       | Core `rel_canonical` + provider + theme fallback                                                               | Theme emits canonical only when no provider is detected, and only for the cases core does not cover; never removes core's.                                                                                                                                           |
| Two robots meta tags                 | Printing a second `<meta name="robots">`, or adding a `wp_robots` filter after Rank Math has cleared the chain | Theme never prints the tag; it filters `wp_robots` (core, Yoast) or `rank_math/frontend/robots` (Rank Math), chosen by the detected provider.                                                                                                                        |
| Conflicting robots directives        | Theme `noindex` on staging vs provider `index`                                                                 | Theme callbacks run after the provider's (`PHP_INT_MAX` on `wp_robots`, default priority on the Rank Math filter) and replace the `index`/`follow` entries instead of appending, so the tag stays congruent; negative directives win per Google's rules in any case. |
| Two JSON-LD graphs                   | Provider graph + theme graph                                                                                   | Theme graph off whenever a provider is detected; per-piece opt-in only through explicit configuration.                                                                                                                                                               |
| Two sitemaps                         | Core + provider                                                                                                | Providers already disable core sitemaps; the theme never registers a sitemap.                                                                                                                                                                                        |
| Two sets of social tags              | Provider OG + theme fallback                                                                                   | Same rule as JSON-LD.                                                                                                                                                                                                                                                |
| Provider active but feature disabled | e.g. Yoast with Open Graph off                                                                                 | Treated as an editorial decision: the theme stays silent for that domain unless a per-feature override is configured.                                                                                                                                                |
| Staging indexed                      | Nothing in the theme today; only `blog_public`                                                                 | Indexability policy (section 02-implementation-plan.md) plus server-side checklist; `robots.txt` alone is not protection.                                                                                                                                            |
| Dormant provider                     | Rank Math before registration skip                                                                             | Detection by constant means the theme stays silent even while the plugin is dormant; documented in the operator guide (complete the plugin setup).                                                                                                                   |
| Must-use `login-slug`                | 404 for `wp-login.php`/`wp-admin`                                                                              | No SEO impact; those URLs are already excluded by `robots.txt`.                                                                                                                                                                                                      |

## 7. Gaps versus the mission

1. No meta description anywhere without a provider.
2. No canonical for home, archives, search, paginated pages without a provider.
3. No Open Graph / Twitter metadata without a provider.
4. No structured data (WebSite, Organization, WebPage, Article, BreadcrumbList) without a provider; no entity identity configuration (legal name, logo, contacts, profiles).
5. No environment indexability policy: a staging copy with `blog_public = 1` is indexable; nothing reads `WP_ENVIRONMENT_TYPE` for SEO.
6. No crawler policy and no documentation of AI crawler tokens.
7. No breadcrumb data (optional) and no editorial semantics beyond the current page header.
8. No diagnostics (what the theme emits, what the provider owns, which environment the site believes it is in).
9. No automated tests for head output, duplicates or provider states.
10. No multilingual or e-commerce compatibility rules for the above.

## 9. Constraints inherited from the repository

- White-label: no vendor names, no agency data, no fictional defaults in code, configuration or documentation shipped to clients; the residue scan must stay green.
- No autoloaded options added by the theme; configuration lives in code (filters) and in the existing ACF options page (already autoloaded), with validation on read.
- Services are small `Registrable` classes registered in `Theme::SERVICES`; data is prepared in PHP, rendered in Twig; escaping at output.
- Release ZIP ships runtime files only; `docs/` and tests never ship. CI must stay green (`php`, `assets`, `e2e`).
- No new admin UI, no new dependencies, no JavaScript for SEO/GEO.
