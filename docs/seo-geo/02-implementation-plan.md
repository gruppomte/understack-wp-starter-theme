# SEO/GEO Foundation — Phase 0: Implementation Plan

Date: 2026-10-08 · Branch: `feature/seo-geo-foundation` (from `v2027.1`, commit `8308adb`) · Status: approved on 2026-10-08 with decisions D-01…D-12 at their recommended defaults; Increments A (Phases 1–3), B (Phase 4) and C (Phases 5–7 compatibility and diagnostics) implemented, see `03-configuration.md`, `04-structured-data.md`, `05-crawler-policy.md`, `06-content-semantics.md`, `07-compatibility.md` and sections 15–17. Companion documents: `00-audit.md` (measured baseline) and `01-ownership-matrix.md` (who owns each signal).

## 1. Goal and success criteria

Add a native SEO/GEO layer to the starter that:

1. Fills, without any SEO plugin, the gaps WordPress core leaves (description, non-singular canonicals, social metadata, structured data, breadcrumb data), using only data that already exists on the site.
2. Goes silent, signal by signal, when Rank Math, Yoast or another supported provider is active, so no page ever carries two canonicals, two robots tags, two descriptions, two social sets or two JSON-LD graphs.
3. Prevents accidental indexing of local, development and staging copies through explicit configuration, while documenting that real protection lives at the server.
4. Ships white-label: every site-specific value is configured per project, validated on read, and omitted when missing. No vendor, agency or placeholder data in code, configuration or output.
5. Stays within the repository's conventions: small `Registrable` services, PHP data preparation, Twig rendering, PHPStan level 5, PHPCS, Prettier, existing test harnesses, release ZIP with runtime files only.
6. Adds no JavaScript, no external requests, no new dependencies, no autoloaded options beyond the identity fields on the existing ACF options page, and no admin screens.

Done means: every supported combination in section 12 passes its tests, `npm run check` and CI stay green, the head report shows one owner per signal, and the operator documentation in section 13 exists.

## 4. Request lifecycle

1. `after_setup_theme`: `Config` is built once (defaults ← `config/seo.php` ← filter) and validated. Invalid values fall back to defaults and are listed in diagnostics.
2. `wp` (priority 20, after core query parsing and WPML/WooCommerce hooks): `PageContext` is built; `ProviderDetector` runs; `Ownership` is resolved. Nothing is output.
3. `wp_headers`: non-production adds `X-Robots-Tag: noindex, nofollow` to every front-end response WordPress serves.
4. `wp_head`:
   - priority 1 (core): `<title>`, `<meta name="robots">` (core + theme directives, plus Yoast's, merged by core's `wp_robots`). With Rank Math the core tag is empty because the plugin clears the `wp_robots` chain on `wp`; its own tag, including the theme's environment directives from `rank_math/frontend/robots`, is printed in its block below.
   - priority 1 (provider): the provider's whole head block, when present.
   - priority 2 (theme `Meta\Head`): only the signals the theme owns, in the order description → canonical → Open Graph → Twitter → JSON-LD.
   - priority 10 (core): `rel_canonical` on singular (untouched).
5. `timber/context`: `seo.breadcrumbs` (when enabled) for templates.
6. `robots_txt` and sitemap filters run only on their own endpoints.

Gates: no theme output when `is_admin()`, `is_feed()`, `is_embed()`, `wp_doing_ajax()`, `REST_REQUEST`, `is_preview()` (except description), `is_customize_preview()`, or when `Config.enabled` is false.

## 6. Behaviour per signal (fallback mode, no provider)

- **Title**: core builds it. Theme adjusts `document_title_parts['title']` on term archives (name without "Categoria:" prefix), post type archives (label), author (display name), date (localized), paged pages keep core's page part. The visible `h1` from `get_the_archive_title()` is untouched.
- **Description** (max 160 characters, cut at a word boundary with an ellipsis only when cut, whitespace normalized, tags/blocks/shortcodes stripped without running `the_content` filters): singular → manual excerpt → page lead (`page_lead` ACF field) → trimmed content; static front page → same rules; posts index → excerpt/lead of the posts page, else none; term archives → term description; author → user description; post type archive → `description` from `register_post_type`; date, search, 404, paged > 1 → none. Password-protected, non-published and preview content → none from content.
- **Canonical**: singular stays core. Theme adds absolute, self-referencing canonicals built from permalink functions (never from the request URI): front page, posts index, term, author, date, post type archive, each with `get_pagenum_link()` when paged. None on search, 404, preview. Query strings are dropped by construction; trailing slash follows permalink settings; host and scheme come from `home_url()` (WPML-aware).
- **Robots**: theme never prints the tag. Without a provider it adds, through `wp_robots`, `noindex` on 404 and on attachment pages (if enabled), configured `noindex` per type, and `noindex, nofollow` on non-production. Search keeps core's `noindex, follow`. No `max-snippet` or other defaults (core already emits `max-image-preview:large`). With a provider only the environment directives remain, delivered through `wp_robots` at `PHP_INT_MAX` (Yoast merges at `PHP_INT_MAX - 10`) or through `rank_math/frontend/robots`; in both cases the theme replaces `index`/`follow` with `noindex`/`nofollow` rather than appending contradictory values.
- **robots.txt**: core virtual file + configured groups, each validated (token `[A-Za-z0-9_.\-]+`, paths starting with `/`, no control characters). A physical file wins and is reported by diagnostics.
- **Sitemap**: core; `noindex` types/taxonomies removed; users provider removed when configured.
- **Social**: `og:type` (`article` for article post types, `website` otherwise), `og:title` (document title), `og:description` (only with a description), `og:url` (only with a canonical), `og:site_name`, `og:locale`, `og:image` + width/height/alt (featured image → default image → none), `article:published_time`/`modified_time` on articles; `twitter:card`, `twitter:title`, `twitter:description`, `twitter:image`, `twitter:site` (only if configured). Nothing on search, 404, preview.
- **Structured data**: section 7.
- **Breadcrumbs**: home → post type archive (if any) → ancestors (pages) or primary term parents (posts, first term by name unless a project filter picks one) → current; term archive → parent terms → current; paged suffix as the last item; strings translatable; URLs from permalink functions. Not on 404/search; not on WooCommerce pages.

## 7. Structured data graph

- Output: one `<script type="application/ld+json">` with `{"@context":"https://schema.org","@graph":[…]}`, serialized with `wp_json_encode($graph, JSON_UNESCAPED_SLASHES | JSON_UNESCAPED_UNICODE | JSON_HEX_TAG | JSON_HEX_AMP | JSON_HEX_APOS | JSON_HEX_QUOT)`; `JSON_HEX_TAG` prevents `</script>` injection. Text values are decoded from entities and stripped of tags. `null`, `''`, `[]` are pruned recursively.
- `@id` scheme: `{home}/#website`, `{home}/#organization`, `{canonical}#webpage`, `{canonical}#article`, `{canonical}#breadcrumb`, `{canonical}#primaryimage`, `{home}/#/schema/person/{user_nicename}`, `{home}/#/schema/logo`.
- Pieces and their conditions:

| Piece                                                                                                          | Condition                                                                     | Properties (only when present)                                                                                                                                                                                                                  |
| -------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `WebSite`                                                                                                      | every indexable page                                                          | name, url, inLanguage, publisher → organization, potentialAction `SearchAction` (`{home}/?s={search_term_string}`)                                                                                                                              |
| `Organization` / `LocalBusiness` subtype                                                                       | identity name configured                                                      | name, legalName, alternateName, url, logo → ImageObject, email, telephone, taxID/vatID, address `PostalAddress`, geo `GeoCoordinates`, openingHoursSpecification, priceRange, areaServed, sameAs                                                |
| `WebPage` / `CollectionPage` / `AboutPage` / `ContactPage` / `ProfilePage` / `SearchResultsPage` (not emitted) | every indexable page; subtype from context or `structured_data.page_types`    | name, url, isPartOf → website, inLanguage, description, datePublished/dateModified (singular), primaryImageOfPage, breadcrumb → breadcrumb (when enabled), about → organization (AboutPage)                                                     |
| `Article` / `BlogPosting`                                                                                      | singular of a configured article post type, published, not password-protected | headline, description, url, mainEntityOfPage → webpage, datePublished, dateModified (ISO 8601 with offset), author → person, publisher → organization (if configured), image → primaryimage, articleSection (categories), inLanguage, wordCount |
| `Person`                                                                                                       | article author or author archive (with `author_profiles`)                     | name, url (author archive only if author archives are indexable), description (public biography), image (avatar only if `show_avatars` and not a Gravatar for a private email → omitted by default), sameAs (user URL field) — never email      |
| `BreadcrumbList`                                                                                               | `breadcrumbs = true` and trail length ≥ 2                                     | itemListElement with position, name, item (last item without URL)                                                                                                                                                                               |
| `ImageObject`                                                                                                  | featured image with dimensions                                                | url, contentUrl, width, height, caption (alt)                                                                                                                                                                                                   |

- Not in the foundation: `FAQPage` (rich result retired by Google on 2026-05-07; an editorial accordion component already exists for visible FAQ content), `Product`/`Offer` (WooCommerce), `Service`, `VideoObject`, `Event`, reviews, ratings, prices. Projects add pieces through `{slug}/seo/graph` with the same pruning and serialization.
- WooCommerce pages: theme graph off (WooCommerce emits `Product`, `BreadcrumbList` and `WebSite` on shop pages). Provider active: theme graph off unless `with_provider` includes `structured_data` (explicit, documented as "you are responsible for duplicates").
- Validation: Schema.org vocabulary checked against the current schema.org definitions during Phase 4; Google Rich Results validation only with the real validator on a public URL (manual step in the checklist, never claimed otherwise).

## 8. Crawler policy (GEO)

- Mechanism: `robots_txt` filter appends validated groups after core's block (`User-agent`, `Allow`, `Disallow`, `Crawl-delay` where the vendor documents it). Nothing by default.
- Documentation deliverable (`docs/seo-geo/05-crawler-policy.md`, Phase 5): verified token table from `00-audit.md` §8 (search vs training vs user-initiated vs ads/preview), what `robots.txt` does and does not govern (user-initiated fetchers from OpenAI and Perplexity are documented as not bound by it), three example policies (default open; training opt-out only; AI search allowed, training disallowed), and the statement that none of this affects Search ranking per the vendors' own pages.
- Infrastructure checklist: CDN/WAF bot management, rate limiting, `robots.txt` served by the web server, staging HTTP authentication, `X-Robots-Tag` for static files, caching of `robots.txt`.
- Not done: user-agent spoofing, live access tests against third-party services, "GEO score", automatic FAQ or content generation, Markdown mirrors, `llms.txt` (reserved key only).
- GEO in the theme means: server-rendered main content (already true), one `h1`, landmarks, descriptive link text, verifiable entity data (identity → JSON-LD), visible author/date metadata on articles (already in `partials/post-meta.twig`), optional breadcrumbs, no hidden bot-only content.

## 9. Multilingual and e-commerce

- **WPML** (`ICL_SITEPRESS_VERSION`): hreflang, language switcher and `x-default` belong to WPML. The theme builds every URL from permalink/`home_url()` functions WPML filters, sets `inLanguage`/`og:locale` from `get_locale()`, translates breadcrumb labels with the theme text domain, and relies on WPML's option translation for identity fields (if the project enables it). Nothing is cached across languages. Status: designed, not certified until a WPML site is available; tests listed in section 12 are marked "pending WPML".
- **WooCommerce** (`WooCommerce` class): theme graph and breadcrumb data off on `is_woocommerce()`, cart, checkout, account; WooCommerce's `noindex` on those pages is untouched; shop canonical from `wc_get_page_permalink('shop')`; product descriptions use the short description through the excerpt rule; no Offer, price, stock or variation data from the theme; nothing on checkout flows. Testable locally in Phase 7 (approved).

## 10. Security and performance requirements

- No `$_SERVER`, `$_GET` or request-header input anywhere in the module; URLs from WordPress functions only.
- Escaping at output: `esc_attr` for meta content, `esc_url` for URLs, JSON flags above for JSON-LD, `sanitize_text_field`/`wp_strip_all_tags` for identity and content-derived strings, allowlists for enumerations.
- No data beyond what is already public on the page: never emails or usernames (nicename is already public in author URLs and is used only as an opaque `@id` fragment), never private/draft/protected content, never prices or stock.
- Diagnostics only in WP-CLI and Site Health (admin capability), never on the front end.
- No external HTTP calls, no transients, no `update_option` at runtime; identity values come from autoloaded options already present on the page lifecycle; image metadata from the object cache.
- Zero JavaScript, zero CSS except the optional breadcrumb partial (Tailwind utility classes already in the design tokens).
- PHPStan level 5, PHPCS and Prettier clean; strict types; `final` classes; readonly value objects.
