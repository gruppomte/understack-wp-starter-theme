# SEO/GEO Foundation — WPML and WooCommerce Compatibility (Increment C)

## 1. WPML (designed, not certified)

WPML is not installed on the local site and no licence is available, so the compatibility is designed against WPML's documented hooks and verified with a mock. It is **not certified** until a real WPML installation is tested.

| Requirement                             | How the theme behaves                                                                                                                                                                                                                               | Verified by                                                                                          |
| --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| No duplicate hreflang                   | The theme never emits `link[rel=alternate][hreflang]`; WPML (or the SEO plugin) owns it                                                                                                                                                             | e2e: no hreflang on the production and staging Playgrounds                                           |
| Canonical per language                  | Canonicals are built from `home_url()`, `get_permalink()`, `get_term_link()` and the archive link functions, all filtered by WPML per language; nothing is derived from the request URL                                                             | Increment A tests; WPML filters: requires WPML                                                       |
| Entity ids and JSON-LD references       | Every `@id` derives from the language home URL and the page canonical, so each language has a coherent graph; `inLanguage` and `og:locale` come from `get_locale()`                                                                                 | Unit tests of the graph; language switching: requires WPML                                           |
| Breadcrumbs with translated hierarchies | Page ancestors, term parents and the posts page come from the translated objects WordPress returns under WPML (`page_for_posts` is filtered by WPML)                                                                                                | Unit tests of the trail; translated hierarchy: requires WPML                                         |
| AboutPage / ContactPage by explicit ID  | Configured page IDs refer to the original page and are mapped through `<slug>/seo/page_id`; `Seo\Integrations\Wpml` implements it with `wpml_object_id` (fallback to the original id); the editorial field on each translated page needs no mapping | Unit test of `Wpml::translate()`; e2e with a WPML mock (constant + filter) on the staging Playground |
| No mandatory dependency                 | The integration registers only when WPML's `SitePress` class exists; the version constant alone is not used because ACF reacts to it and expects WPML's globals                                                                                     | Unit and e2e without WPML                                                                            |
| No URL manipulation                     | The theme never rewrites multilingual URLs or adds language segments                                                                                                                                                                                | Code review                                                                                          |

Tests that need a real WPML site: hreflang set emitted by WPML next to the theme's head; canonical and `og:url` on a translated page; breadcrumb trail of a translated child page; `AboutPage` typing of a translation through the configured original ID; identity fields translated through WPML's options translation; sitemap per language. The diagnostics report WPML as NOT VERIFIED while it is active.

## 2. WooCommerce (verified on the local site, WooCommerce 11.2.0)

| Requirement                                 | Behaviour                                                                                                                                                                                                         | Verified                                                                |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| Product and Offer by the competent provider | The theme emits no product data. WooCommerce prints `Product` (with `AggregateOffer` for variable products) on product pages; with Yoast active, Yoast prints its graph and WooCommerce keeps the `Product` block | Local: product pages with and without Yoast                             |
| No JSON-LD duplication                      | The theme emits no graph on shop pages (`is_woocommerce()`) and nothing on cart, checkout and account pages                                                                                                       | Local head report `08-head-reports/local-woocommerce.md`: no duplicates |
| No invented prices or availability          | Only WooCommerce writes them                                                                                                                                                                                      | Code: no price or stock in the theme                                    |
| No private B2B data                         | The theme reads nothing from orders, customers or prices                                                                                                                                                          | Code review                                                             |
| Canonical on products and categories        | Core on product singles; theme on the shop page, product categories and paginated listings (`/shop/page/2/`, `/product-category/…/page/2/`)                                                                       | Local                                                                   |
| Breadcrumbs without conflicts               | The theme's trail is off on shop and transactional pages; WooCommerce's breadcrumb renders only where a template calls it (the shipped shop template does not)                                                    | Local                                                                   |
| Archive pagination                          | Theme canonicals on paginated shop and category pages; no description on page 2                                                                                                                                   | Local with a 2-per-page catalogue                                       |
| Cart, checkout, account untouched           | Cart and account answer 200 with WooCommerce's `noindex`; checkout redirects to the cart when it is empty; the theme adds no description, social tags or graph there; core canonical stays                        | Local                                                                   |
| Variable products                           | WooCommerce `AggregateOffer` with low and high price, two variations                                                                                                                                              | Local                                                                   |
| Shop page description                       | The shop's own page content (excerpt, lead or body), never WooCommerce's internal post type description                                                                                                           | Code + local (empty shop page → no description)                         |

Limits: WooCommerce was tested with sample products created for the purpose and removed afterwards; checkout with items in the cart, payment flows and account areas were not exercised beyond their HTTP status and head output, because the theme does not touch them. The plugin remains installed and inactive on the local site.
